3Tool contracts

Results are short JSON. They never contain generated code or raw Figma data. Warnings are capped at 5 per chunk. Every result also ends with a usage block: Figma API calls and estimated tokens for that step, and totals for the design. src/usage.js writes the full report to figma2ui/usage-report.md.

figma_index

in  { url, projectDir, stack? }
out { design, stack, dir,
      chunks: [{ id, name, nodes, repeat? }],
      assets: number, tokens: number }

Side effects: caches the design, writes the tokens file, saves state.

figma_chunk

in  { projectDir, ids? }   // omit ids = all
out { page,
      chunks: [{ id, file, lines, assets,
                 warnings? }],
      skipped?, skippedReason? }

Side effects: writes chunk files and always rewrites the page file.

figma_assets

in  { projectDir, ids? }   // omit ids = all
out { dir, total, written, alreadyPresent,
      skipped?, failed?: [{ id, error }] }

Side effects: downloads images and SVG icons. One failed asset does not stop the others.

4Conversion pipeline

Stages 2 to 5 are pure functions of the cached design, so figma_chunk and figma_assets recompute them from the cache instead of storing intermediate results.

Fetchfigma.js · version check, cache, download
Build treetree.js · node to element, drop hidden nodes
Tokenstree.js · colors, fonts, sizes to CSS variables
Dedupechunk.js · structural hash, props
Chunkchunk.js · split at 150 nodes
Emitemit.js · per-stack code or spec
Writeproject.js · guarded write to disk
Summarizetools.js · short JSON to the agent

5Data model

Design (cache entry)

{ name, version,
  document,   // Figma node subtree
  styles,     // style id to { name }
  rawBytes }  // size of the API response

Element (neutral tree)

{ tag,        // div p h1 img button input a
  name,       // Figma layer name
  css,        // { 'flex-direction': 'row', ... }
  children,   // Element[]
  warn,       // string[]
  text?,      // literal text
  attrs?,     // { src, alt, href, placeholder }
  assets?,    // asset file names used
  props? }    // slot to prop name (templates)

// Reference to another chunk:
{ ref, values, assets, children: [] }

Chunk

{ id,         // 'c1', 'c2', ... or 'page'
  name,       // PascalCase, unique
  el,         // Element subtree
  repeat,     // instance count
  props,      // string[]
  nodes,      // size, a ref counts as 1
  assets,     // string[]
  warnings }  // deduped, with counts

Token and asset

Token { name,   // 'color-1', 'size-heading'
        value } // '#1a1a1a', '16px'

Asset { id, file,   // 'svg-1-23.svg'
        kind,       // 'svg' | 'image'
        source }    // node id | imageRef

A token is named after its Figma style when one exists, otherwise by a counter per kind.

6Algorithms

Node mapping (tree.js)

  • Auto-layout becomes flex: direction, gap, padding, justify, align, wrap.
  • Sizing: FILL becomes flex: 1 1 0 on the main axis or align-self: stretch on the cross axis. HUG sets no size. FIXED sets px and flex-shrink: 0.
  • No auto-layout: parent relative, children absolute with offsets from bounding boxes, plus a warning.
  • Vectors, and groups made only of vectors, become one SVG asset.
  • Image fill on a leaf becomes img; on a container, a background image.
  • Layer names matching button, input, or link set the tag. Text tag comes from font size or an h1 to h6 layer name.
  • Root frame: width: 100%, max-width of the frame, centered.

Dedupe (chunk.js)

  1. Hash every element, bottom-up: sha1([tag, css, hasText, attrKeys, childHashes]). Text and image content are left out, so cards with different copy match.
  2. Walk top-down. A subtree is a repeat if its hash occurs more than once, it has at least 3 nodes, and at most 12 text or image slots. More slots means it is a list, so the walk goes inside it.
  3. The first instance becomes the template. A slot whose value differs between instances becomes a prop, named from the layer name.
  4. Each instance is replaced by { ref, values }.

Chunk split (chunk.js)

  1. Each top-level child of the root with 3 or more nodes becomes a chunk.
  2. Inside a chunk, a post-order walk keeps a running node count. When adding a child would pass 150, that child is extracted into its own chunk and counts as 1.
  3. Post-order means a child is already reduced before its parent decides.
  4. What remains of the root becomes the page chunk, which renders the others in order.

Known limits: a frame with over 150 direct leaf children stays oversized, and repeat templates are not split. Both are reported in warnings.

Styling

  • Tailwind, when tailwindcss is a dependency: exact utilities where one exists (flex, items-center), otherwise arbitrary values (gap-[12px], [box-shadow:...]). Works on v3 and v4.
  • Plain CSS otherwise: one Name.css per chunk, classes named design-chunk-n.
  • Tokens are CSS variables on :root in figma-tokens.css, imported by the page.

One renderer, small syntax table

render() walks the element tree once. Per-framework differences live in a table of 4 entries: class attribute name, attribute binding, text interpolation, and component tag. wrap() adds the file shell: imports, props, and style links.

TypeScript is used for React when typescript or tsconfig.json is present.

8Figma API usage

Tier 1 calls are the scarce ones. The design targets one Tier 1 call per new design version, plus one if the design has vector icons.

EndpointUsed byTierWhen
GET /v1/files/:key/metafetchVersion3Every figma_index. A 403 (token lacks the scope) skips the check.
GET /v1/files/:key/nodes?ids=getDesign1Cache miss only. Without a node-id, GET /v1/files/:key and the first page.
GET /v1/images/:key?ids=&format=svgsvgUrls1figma_assets, when SVGs are missing or the file version changed. 100 ids per call.
GET /v1/files/:key/imagesimageFillUrls2figma_assets, when an image fill is not on disk yet.
Presigned asset URLfetchBytesnonePer asset. Sent without the Figma token.

Client behaviour: 120 s timeout per request. On 429, waits for Retry-After and retries up to 3 times if the wait is 60 s or less; a longer wait fails at once with the wait time.

9State and cache

projectDir/.figma2ui.json

{ stack:   { framework, label, styling,
             ext, assets, root },
  current: { fileKey, nodeId, version,
             dir, slug },
  written: { "<relative path>": "<sha256>" },
  assetsVersion }

written records the hash of every generated file. It is what lets a re-run tell an untouched file from an edited one.

Design cache

~/.cache/figma2ui/
  <fileKey>-<nodeId|page>-<version>.json
  • Keyed by Figma file version, so it never serves a stale design.
  • Directory mode 0700, file mode 0600. Written to a temp file, then renamed.
  • A corrupt entry is treated as a miss.
  • FIGMA2UI_CACHE overrides the location.

Output layout

src/figma/<design>/      components, Page,
                         figma-tokens.css
public/figma/            assets
static/figma/            assets (SvelteKit)
figma2ui/<design>/       spec targets
figma2ui/assets/         spec target assets

10Safeguards

Layer names and text come from the design file, so they are treated as untrusted input.

RiskControlWhere
Design text breaking or injecting template codeText and attributes are written as numeric entities for & < > " ' { } ` \ @ and newline, which are literal in JSX, Vue, Svelte, Angular, and HTML.emit.js esc()
Layer name used as a path or identifierNames are reduced to ASCII letters and digits before use.names.js
Writing outside the projectAbsolute projectDir required. Resolved path must be inside src/figma, public/figma, static/figma, or figma2ui. Symlinked output folders are refused.project.js safePath()
Overwriting manual editsA file is replaced only if its hash matches the one recorded at generation. Otherwise it is listed in skipped.project.js writeGenerated()
Token leakRead from FIGMA_TOKEN, sent only to api.figma.com, never logged or cached, not sent to presigned asset URLs.figma.js
Link to a non-Figma hostOnly https links on figma.com or www.figma.com are accepted.figma.js parseFigmaUrl()
Agent following text found in a designSpec files state that quoted strings are design data. The skill file repeats the rule.emit.js, skill/SKILL.md

11Error handling

Every handler error reaches the agent as isError: true with a message that says what to do next.

ConditionBehaviour
FIGMA_TOKEN missingFails before any network call.
403 from FigmaFails: token invalid or no access. On the meta endpoint only, continues without a version check.
404, or node not in fileFails with a prompt to check the link.
429 with a long waitFails at once, with the wait in hours and a note on seat limits.
Figma Make link, or a Make code layer as rootFails: no design layers to convert. A nested code layer is only a warning.
Stack not detectedFails and tells the agent to ask the user, then pass stack.
figma_chunk or figma_assets before figma_indexFails: call figma_index first.
Unknown chunk or asset idFails and lists the unknown ids.
One asset download failsRecorded under failed. Other assets continue.

12Tests and open items

Covered

  • 30 node:test cases in test/figma2ui.test.js, with fetch mocked.
  • URL parsing, flex mapping, absolute fallback, dedupe and props, chunk limit, stack detection, escaping, each emitter, path and symlink guards, edit protection, cache reuse, rate-limit errors.
  • Generated output accepted by esbuild (React), the Vue and Svelte compilers, the Angular template parser, and Tailwind v4.
  • Server answers tools/list over stdio.

Not yet verified

  • A full run on a real layered Figma design, with a visual comparison.
  • The /meta version check against the real API.
  • Registration inside each AI tool.

Out of scope in this version

  • Native code generators for mobile stacks.
  • Breakpoint-specific layouts, interactions, animation.
  • Reuse of existing project components.
  • Rotation, blend modes, and mixed text styles, which are flagged in warnings.
